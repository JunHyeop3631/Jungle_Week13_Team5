# Solver — 배경과 로직 정리

> Unreal Engine 4.x / PhysX 4.1 기준

## 1. 왜 Solver가 필요한가 (배경)

### 근본 문제: Data Coupling
물리 현상은 여러 요소가 **동시에 상호의존적**으로 일어나지만, 컴퓨터 연산은 본질적으로 **순차적**이다. 이 미스매치가 solver의 존재 이유다.

```
현실   : 본 A,B,C가 연결돼 한 순간에 동시에 서로 당기고 밀침
컴퓨터 : A 계산 → B 계산 → C 계산 (하나씩)
         그런데 A를 풀려면 B가 필요하고, B를 풀려면 A가 필요함 (닭-달걀)
```

- 제약(constraint)들이 서로 얽혀(coupling) 있어 **한 번의 순차 패스로 정확히 못 푼다**
- 단일 코어든 멀티 코어든 상관없음 — **얽힘 자체**가 한 방에 못 푸는 원인
- 정확히 푸는 건 너무 비싸므로 → **근사를 반복해 수렴**시킨다

### Solver가 푸는 대상: 제약(Constraint)
narrow-phase가 만들어준 "지켜야 할 조건"들:
- **충돌 접촉**: "서로 파고들면 안 된다, 밀어내라"
- **Joint**: "이 두 본은 붙어 있어야 하고, 정해진 각도만 꺾인다"
- 이 제약들이 **서로 얽혀 동시에** 만족돼야 함

## 2. Solver 로직

### 입력과 목표
```
입력 : 제약 목록 (충돌 접촉들 + joint들)
목표 : 모든 제약을 (근사적으로) 동시에 만족하는 속도·위치 찾기
```

### 핵심: 반복 보정 (Gauss-Seidel류)
```
for (iteration 1..N):          ← N = solver iteration count = phase 횟수
    for each 제약:              ← 한 phase 안: 순차 처리
        ① 지금 얼마나 어긋났나 측정 (오차)
        ② 어긋남을 줄이도록 관련 바디 속도 보정
        ③ 다음 제약으로 (방금 결과를 즉시 반영)
```

- 하나 고치면 얽힌 다른 게 틀어짐 → 다음 바퀴가 또 보정 → 점점 수렴
- **한 바퀴(loop) = 한 phase**, 완전 해결 안 되므로 여러 바퀴 반복

### 2단계 구조 (PhysX 실제)
```
1. Velocity solver : 충돌·joint 만족하도록 속도 보정 (반복 루프)
2. Integration     : 보정된 속도로 위치 전진 (새위치 = 현위치 + 속도×dt)
3. Position solver : 적분 후 남은 침투를 위치로 직접 보정 (반복 루프)
```
→ UE4에 position/velocity iteration이 따로 있는 이유

## 3. 순차성과 병렬성의 층위

| 구분 | 처리 방식 | 이유 |
|---|---|---|
| **phase 간** (iteration 사이) | **순차 필수** | iteration 2는 1의 결과 위에서 시작 → 건너뛸 수 없음 |
| **phase 안, 얽힌 제약** | **순차가 유리** | 방금 보정 결과를 즉시 읽어 수렴 가속 (Jacobi보다 빠름) |
| **phase 안, 안 얽힌 제약** | **병렬 가능** | 왼팔 joint ↔ 오른발 joint는 서로 안 읽음 → 동시 처리 |

> **핵심**: 반복의 원인은 **coupling**이지 병렬이 아니다. 병렬화는 그 위에 얹은 **속도 최적화**(독립 제약만 동시에)일 뿐.

---

## 4. Iteration Count의 의미

```
반복 횟수↑ = 단단·정확·느림  (얽힘을 충분히 수렴시킴)
반복 횟수↓ = 물렁·떨림·빠름  (어긋남이 남은 채 중단)
```

### 증상 ↔ 원인 매핑 (ragdoll 등)
- joint가 고무처럼 늘어짐 → iteration 부족
- 본/물체가 서로 파고듦 → iteration 부족 (침투 미해소)
- 관절이 부들부들 떨림 → iteration 부족
- → ragdoll 튜닝 = 사실상 **solver iteration + joint 설정** 튜닝

---

## 5. 전체 흐름에서의 위치

```
simulate(dt):
   Broad-phase   : 부딪힐 만한 쌍 추림
   Narrow-phase  : 정확한 접촉점·관통깊이 계산 → "제약 목록" 생성
   ┌────────────────────────────────────────┐
   │ Solver : 제약들을 반복 풀이로 동시 만족   │  ← 여기
   └────────────────────────────────────────┘
   Integration   : solver가 정한 속도로 위치 갱신
```

---

## 한 줄 요약
> Solver = 충돌·joint 같은 제약들이 **서로 얽혀(coupling)** 한 번에 못 풀리므로, **phase(iteration)로 나눠** 각 phase 안에서는 의존 순서대로 처리하고, 이를 **근사로 반복**해 원하는 물리 결과(속도·위치)에 수렴시키는 PhysX의 핵심 단계.
