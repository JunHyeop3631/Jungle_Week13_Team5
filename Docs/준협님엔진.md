## PHASE 2 — 4인 역할 분담 예측

> 분담 원칙: **(A) 의존성 순서**(토대→상위) + **(B) 병렬성 극대화**(대기·충돌 최소화)를 동시 충족.
> 진단 결과를 반영한 핵심 판단:
> - 영역 1이 거의 완료 → "토대 구축자" 부담은 작음. 대신 **`PhysXPhysicsScene.cpp` 단일 파일의 동시 수정**이 진짜 병목 → **단일 오너 + API 경유** 전략.
> - 영역 4(DOF)는 물리와 완전 독립 + 토대 완비 → **1일차부터 풀기간 병렬**.
> - 영역 5(Cloth)의 리스크는 코드가 아니라 **외부 빌드(NvCloth 1.1.6+CUDA 10.0)** → 한 명 집중 회피 위해 **시뮬/빌드(물리) ↔ 렌더측 정점버퍼(렌더)** 자연 이음새로 분할.

| **M1** | 영역1 잔여 + PhysX 씬/인터페이스 + Cloth 시뮬/빌드 | 없음(선행) | `PhysXPhysicsScene`/틱루프, `FBodyInstance`·등록 API, 타입매핑 |
| **M2** | 영역2 PhysicsAsset 데이터모델 + 에디터 UI | M1(인터페이스 스텁) | `SkeletalMeshComponent` 물리 멤버 레이아웃 |
| **M3** | 영역3 Ragdoll(조인트·본 역주입·디버그) | M1(조인트 API)+M2(바디 데이터) | 디버그 렌더 내용, 물리→본 write-back 경로 |
| **M4** | 영역4 DOF + 공유 ShowFlag 인프라 + Cloth 렌더측 | 없음(병렬) | `FShowFlags`/Stat/디버그토글 enum |

#### ☑ 권장 착수 순서 + 초반 동기화 포인트 (1주차 인터페이스 합의 회의 확정 항목)
- **착수 순서**: ① M1(영역1 잔여)·M4(DOF) **1일차 병렬** → ② M1이 인터페이스 스텁 납품 후 M2 본격 착수 → ③ M2 데이터모델 + M1 조인트 API 도달 후 M3 본격화(그 전엔 디버그렌더/역주입 프로토타입) → ④ Cloth는 M1(빌드/시뮬)이 인터페이스 납품 후, M4(렌더측)는 DOF 마무리 후 합류.
- **1주차 회의 확정 항목**: (1) `FBodyInstance` 시그니처 (2) 본단위 바디/조인트 등록 API (3) `FShowFlags` enum 추가분 전체 (4) `SkeletalMeshComponent` 물리 멤버 레이아웃 (5) 물리→본 역주입 우선순위 규약 (6) cloth 동적 정점버퍼 갱신 규약.

#### ⚠ 리스크 편중 경고 + 보조 배정
- **최대 리스크 = M1 이중 임계**: Cloth(NvCloth 1.1.6+CUDA 10.0) 외부 빌드가 M1에 몰리는데, M1은 동시에 **2·3을 막는 인터페이스 오너**다. Cloth 빌드가 지연되면 M2/M3까지 연쇄 지연.
  - **완화 (a)**: M1은 **인터페이스 납품을 Cloth보다 절대 우선**(Cloth는 인터페이스 동결 후 착수).
  - **완화 (b)**: Cloth를 **M1(시뮬/빌드) + M4(렌더측 정점버퍼)** 로 분할 — 단일 집중 회피.
  - **완화 (c)**: **CUDA 10.0 환경 셋업을 1주차 별도 스파이크로 선검증** → 실패 시 NvCloth CPU-only 폴백 조기 결정(일정 보호).
- **대안 배정**: Cloth 빌드가 1주차 스파이크에서 고위험으로 판명되면, M3가 래그돌 임계경로라 여력이 없으므로 **M4가 Cloth 전체를 흡수하고 DOF를 M1로 이관**하는 스왑이 차선책(M1은 영역1이 가벼워 DOF 수용 여지 있음).
